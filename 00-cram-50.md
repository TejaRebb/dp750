## A. Compute

**1. Which compute for which workload?**
- Scheduled production job: **job compute** (cheapest; exists only for the run).
- Interactive notebooks: all-purpose compute.
- SQL and BI dashboards: SQL warehouse.
- Fast start with nothing to manage: serverless.

**2. Standard or dedicated access mode?**
- Standard: many users on one cluster, isolated from each other. Default choice.
- Dedicated: one user or one group. Required for the ML runtime, GPUs, R and RDD APIs.
- Both enforce Unity Catalog.
- Compute permissions, lowest to highest: CAN ATTACH TO, CAN RESTART, CAN MANAGE.

**3. What do autoscaling, auto-termination, pools, policies and Photon each do?**
- Autoscaling: min–max workers for variable load.
- Auto-termination: shuts down idle all-purpose compute.
- Pools: idle ready VMs for faster cluster start. No DBU charge while idle; Azure VM cost still applies.
- Cluster policies: limit what users can configure. Cost control.
- Photon: faster SQL and DataFrame queries. No gain for Python UDFs or RDD code.

**4. How do you install a library?**
- For the whole cluster: compute-scoped library (PyPI, Maven, or a wheel/JAR in a volume).
- For one notebook: `%pip install`.
- On serverless: the Environment panel (dependency list).
- For OS-level setup: init script.

## B. Unity Catalog objects

**5. What is the hierarchy?**
- Metastore (one per region) → catalog → schema → table, view, volume, function, model.
- Names have three parts: `catalog.schema.table`.
- Isolate environments with one catalog each (dev, test, prod); bind a catalog to specific workspaces.
- Trap: catalogs and schemas take `MANAGED LOCATION`. Only external tables and volumes take `LOCATION`.

**6. Managed table, external table, or volume?**
- Managed table: Databricks owns the files. `DROP` deletes the data; `UNDROP` works for 7 days. Default choice.
- External table: has `LOCATION 'abfss://…'`. `DROP` removes metadata only; files stay. Pick it when other tools read the files directly.
- Volume: non-tabular files (CSV, JSON, images). Path is `/Volumes/catalog/schema/volume/file`.

**7. View, materialized view, or streaming table?**
- View: saved query; runs every time.
- Materialized view: stored result, refreshed incrementally when possible. Aggregations for BI.
- Streaming table: incremental append-only ingestion; each row is processed once.
- Temporary view: lasts for the session; not in Unity Catalog.

**8. How do you query an external database without copying it?**
- Lakehouse Federation: `CREATE CONNECTION` (host and credentials), then `CREATE FOREIGN CATALOG … USING CONNECTION …`.
- It's read-only and governed by Unity Catalog grants.

## C. Access and authentication

**9. What are the minimum grants to query one table?**
```sql
GRANT USE CATALOG ON CATALOG prod TO `analysts`;
GRANT USE SCHEMA ON SCHEMA prod.sales TO `analysts`;
GRANT SELECT ON TABLE prod.sales.orders TO `analysts`;
```
- All three are required. `SELECT` alone fails.
- Grants inherit downward: `SELECT` on a schema covers every current and future table in it.
- Writing needs `MODIFY`. Seeing metadata only needs `BROWSE`.
- Grant to account groups, not to individual users.
- The owner, or anyone with `MANAGE` on the object, can grant.

**10. How do you read an Azure Key Vault secret?**
- Create a Key Vault-backed secret scope, then `dbutils.secrets.get(scope="kv", key="sql-pwd")`.
- Notebook output shows `[REDACTED]`.
- The scope is read-only from Databricks; secrets are managed in Azure.
- In Spark config: `{{secrets/kv/sql-pwd}}`.
- Trap: the vault must use the "Vault access policy" permission model, not Azure RBAC.

**11. Managed identity or service principal?**
- Managed identity (through an Access Connector for Azure Databricks): how Unity Catalog reaches ADLS storage. No secret to rotate. Give it Storage Blob Data Contributor.
- Service principal: the identity for automation, such as a job's "Run as", CI/CD deployments and API calls. It signs in with OAuth (client ID and secret), not a personal access token.

**12. Storage credential or external location?**
- Storage credential: the identity that can reach storage.
- External location: a storage path plus a storage credential.
- Grants on an external location: `READ FILES`, `WRITE FILES`, `CREATE EXTERNAL TABLE`, `CREATE EXTERNAL VOLUME`.

## D. Governance

**13. Row filter, column mask, or dynamic view?**
```sql
CREATE FUNCTION us_only(region STRING)
  RETURN is_account_group_member('admins') OR region = 'US';
ALTER TABLE sales SET ROW FILTER us_only ON (region);

CREATE FUNCTION mask_ssn(ssn STRING)
  RETURN CASE WHEN is_account_group_member('hr') THEN ssn ELSE '***' END;
ALTER TABLE emp ALTER COLUMN ssn SET MASK mask_ssn;
```
- Row filter hides rows; its function returns a boolean.
- Column mask replaces values; its function returns the column's type.
- Dynamic view: a view that uses `is_account_group_member()` or `current_user()`. Pick it when users must not touch the base table, or need a joined or reshaped result.

**14. What is ABAC and when do you pick it?**
- Governed tags (defined at account level) plus policies attached to a catalog, schema or table.
- A policy applies a row filter or column mask to every table or column that carries the tag, including new ones.
- Pick it for "one rule across many tables" or "table owners must not be able to remove the rule".
- Policies don't grant access. Users still need `SELECT`.

**15. Where do you find lineage, history and audit logs?**
- Catalog Explorer, on the table: owner and comments, History (Delta versions), Lineage (upstream and downstream tables, columns, notebooks, jobs), Dependencies.
- Lineage is captured automatically for Unity Catalog objects. Query it in `system.access.table_lineage` and `column_lineage`.
- Audit log: `system.access.audit`.
- Discovery: `COMMENT ON TABLE`, column comments, tags; in a Genie space, add instructions and example SQL.
- Trap: a job's DAG shows task order, not data lineage.

**16. Delta Sharing: Databricks-to-Databricks or open?**
- The provider creates a share and a recipient: `GRANT SELECT ON SHARE s TO RECIPIENT r`.
- Databricks-to-Databricks: the recipient has Unity Catalog and gives a sharing identifier. No token.
- Open sharing: any client (Power BI, pandas, Spark) with a bearer token from an activation link.
- Sharing is read-only and live, with no copy.
- Securing it: token expiry, IP access lists, share views or partitions instead of whole tables, audit logs.

**17. How do you set data retention on a table?**
- `delta.deletedFileRetentionDuration` (default 7 days): how long old data files stay. This is the time-travel window.
- `delta.logRetentionDuration` (default 30 days): how long the history stays.
- `VACUUM` physically deletes files older than the retention.
- Permanently removing a person's data: `DELETE`, then `REORG TABLE t APPLY (PURGE)`, then `VACUUM`.

## E. Ingestion

**18. Which ingestion tool?**
- SaaS apps and databases (Salesforce, Workday, SQL Server), managed and incremental: Lakeflow Connect. It lands data as streaming tables; database sources need an ingestion gateway.
- Files arriving in ADLS continuously, with schema drift: Auto Loader.
- Simple repeatable SQL file load: `COPY INTO`.
- Orchestration across Azure services or on-premises sources: Azure Data Factory, which calls a Databricks notebook or job activity.
- Custom logic or REST APIs: notebook.

**19. What must you know about Auto Loader?**
```python
(spark.readStream.format("cloudFiles")
  .option("cloudFiles.format", "json")
  .option("cloudFiles.schemaLocation", schema_path)
  .load(src)
  .writeStream.option("checkpointLocation", cp)
  .trigger(availableNow=True).toTable("bronze"))
```
- `cloudFiles.schemaLocation` is required for schema inference and evolution.
- `cloudFiles.schemaEvolutionMode`: `addNewColumns` (default; the stream stops once and the restart adds the column), `rescue` (schema never changes; new columns go to `_rescued_data`), `failOnNewColumns`, `none`.
- JSON and CSV columns are inferred as strings unless `cloudFiles.inferColumnTypes` is true. Force a type with `cloudFiles.schemaHints`.
- The first run reads the files already in the folder.
- SQL form: `FROM STREAM read_files('path', format => 'json')`.

**20. `COPY INTO`, CTAS, `CREATE OR REPLACE`, or `INSERT`?**
- `COPY INTO t FROM 'path' FILEFORMAT = CSV`: idempotent; skips files it already loaded.
- `CREATE TABLE t AS SELECT` (CTAS): creates and loads once; schema comes from the query.
- `CREATE OR REPLACE TABLE`: replaces data and schema but keeps history and grants. Better than DROP then CREATE.
- `INSERT INTO`: appends; re-running duplicates rows.
- `INSERT OVERWRITE`: replaces the data; schema must match.

**21. How do you stream from Azure Event Hubs?**
- Use the Kafka connector: `spark.readStream.format("kafka")`.
- `kafka.bootstrap.servers` is `<namespace>.servicebus.windows.net:9093`; `subscribe` is the event hub name.
- `kafka.security.protocol` is `SASL_SSL`. `kafka.sasl.mechanism` is `PLAIN` (connection string from a secret scope) or `OAUTHBEARER` (Entra ID).
- The payload is binary: `CAST(value AS STRING)`, then `from_json`.

**22. How do you apply a CDC feed?**
```sql
CREATE OR REFRESH STREAMING TABLE dim_customer;
CREATE FLOW cdc AS AUTO CDC INTO dim_customer
FROM STREAM(cdc_feed)
KEYS (customer_id)
APPLY AS DELETE WHEN op = 'DELETE'
SEQUENCE BY op_ts
STORED AS SCD TYPE 2;
```
- `SEQUENCE BY` puts out-of-order events in the right order.
- Python: `dp.create_auto_cdc_flow(target, source, keys, sequence_by, stored_as_scd_type=2)`.
- Outside pipelines: `MERGE INTO` inside `foreachBatch`.
- Reading changes out of a Delta table: Change Data Feed. Set `delta.enableChangeDataFeed = true`, then `table_changes('t', 5)`.
- `_change_type` values: `insert`, `update_preimage`, `update_postimage`, `delete`.

## F. Modeling and layout

**23. Liquid clustering, partitioning, or Z-order?**
- Liquid: `CLUSTER BY (a, b)`, up to 4 keys, or `CLUSTER BY AUTO`. Keys can change later without a rewrite. Default for new tables; best for high-cardinality filters and skew.
- Partitioning: low-cardinality columns on tables over 1 TB only. Fixed at creation.
- Z-order: `OPTIMIZE t ZORDER BY (a)`. Legacy; rewrites data on every run.
- Trap: liquid clustering can't be combined with partitioning or Z-order.
- Clustering is applied when `OPTIMIZE` runs, not on insert.

**24. What are deletion vectors?**
- DELETE, UPDATE and MERGE mark rows as removed in a small side file instead of rewriting the Parquet file. Writes get faster.
- The rows are physically gone only after `OPTIMIZE` or `REORG TABLE t APPLY (PURGE)`, followed by `VACUUM`.

**25. SCD Type 1 or Type 2?**
- Type 1: overwrite; no history. Example: fixing a typo.
- Type 2: a new row per change with `__START_AT` and `__END_AT`. The current row has `__END_AT` = NULL.
- "Report the value as it was on a past date": Type 2.
- Time travel is for short-term audit and rollback. It is not a long-term history table.

**26. Which table format?**
- Delta: the default. ACID, time travel, MERGE.
- Iceberg: when external Iceberg engines must read the table (managed Iceberg table, or Delta with UniForm).
- Parquet: columnar, no transactions.
- CSV and JSON: raw landing files only.
- Parquet to Delta in place: `CONVERT TO DELTA`.

**27. Batch or streaming, and what grain and types?**
- Batch: data arrives on a schedule and hours of latency are fine.
- Streaming: data arrives continuously or latency must be low.
- Incremental batch: streaming code with `trigger(availableNow=True)` on a schedule.
- Grain: store the lowest level needed (one row per order line); aggregate in gold.
- Types: money is `DECIMAL(p,s)`, not DOUBLE; dates are `DATE` or `TIMESTAMP`, not STRING.

## G. Transform

**28. What is the MERGE syntax?**
```sql
MERGE INTO tgt t USING src s ON t.id = s.id
WHEN MATCHED AND s.op = 'D' THEN DELETE
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *
WHEN NOT MATCHED BY SOURCE THEN DELETE;
```
- Trap: two source rows matching one target row is an error. Deduplicate the source first.
- New source columns: `MERGE WITH SCHEMA EVOLUTION INTO …`.

**29. How do you remove duplicates and handle nulls?**
- Whole-row duplicates: `dropDuplicates()` or `SELECT DISTINCT`. By key: `dropDuplicates(["id"])`.
- Keep the latest row per key: `QUALIFY ROW_NUMBER() OVER (PARTITION BY id ORDER BY ts DESC) = 1`.
- In a stream: `withWatermark(…)` plus `dropDuplicatesWithinWatermark(["id"])`.
- Nulls: `coalesce(col, 'x')`, `fillna()`, `dropna()`, `WHERE col IS NOT NULL`.

**30. Which set operator or join?**
- `UNION` removes duplicates; `UNION ALL` keeps them.
- `INTERSECT`: rows in both. `EXCEPT`: rows in the first but not the second. Both remove duplicates unless you add `ALL`.
- Trap: PySpark `union()` matches columns by position and keeps duplicates. `unionByName()` matches by name.
- `LEFT SEMI`: left rows that have a match. `LEFT ANTI`: left rows with no match.

**31. How do you pivot and unpivot?**
```sql
SELECT * FROM sales
PIVOT (SUM(amount) FOR quarter IN ('Q1', 'Q2', 'Q3', 'Q4'));

SELECT * FROM wide
UNPIVOT (amount FOR quarter IN (q1, q2, q3, q4));
```
- PIVOT turns rows into columns and needs an aggregate. UNPIVOT turns columns into rows.
- PySpark: `df.groupBy("id").pivot("quarter").sum("amount")`.
- Denormalizing: join dimensions into one wide table so queries need fewer joins. Used in gold.

**32. How do you profile data?**
- In a notebook: `display(df)` then the data profile option, or `dbutils.data.summarize(df)`.
- In code: `df.describe()` (count, mean, stddev, min, max) and `df.summary()` (adds quartiles).
- Distinct counts and null counts: `approx_count_distinct(col)`, `count_if(col IS NULL)`.

## H. Data quality

**33. Schema enforcement or schema evolution?**
- Enforcement: Delta rejects a write whose schema doesn't match.
- Adding columns on append: `.option("mergeSchema", "true")`.
- Replacing the schema: `.mode("overwrite").option("overwriteSchema", "true")`.
- Renaming or dropping a column: column mapping (`delta.columnMapping.mode = 'name'`).
- Drifting source files: Auto Loader schema evolution plus `_rescued_data`.

**34. Which constraints does a Delta table enforce?**
```sql
ALTER TABLE t ALTER COLUMN id SET NOT NULL;
ALTER TABLE t ADD CONSTRAINT amt_ok CHECK (amount >= 0);
```
- A write that violates either one fails as a whole.
- Trap: PRIMARY KEY and FOREIGN KEY are informational and not enforced.
- Checking uniqueness yourself: `GROUP BY id HAVING COUNT(*) > 1`.
- Type checks: `try_cast()` returns NULL where a plain cast would fail.

**35. What are the three expectation behaviors in a pipeline?**
- `CONSTRAINT c EXPECT (cond)`: keeps the row and records the violation. This is the default. Python `@dp.expect`.
- `… ON VIOLATION DROP ROW`: drops the row. Python `@dp.expect_or_drop`.
- `… ON VIOLATION FAIL UPDATE`: stops the update. Python `@dp.expect_or_fail`.
- Several rules at once: `expect_all`, `expect_all_or_drop`, `expect_all_or_fail`.
- Results appear in the pipeline event log.

## I. Pipelines and streaming

**36. Streaming table or materialized view in a pipeline?**
- Streaming table: `CREATE OR REFRESH STREAMING TABLE … FROM STREAM(src)`. Append-only sources; bronze and silver ingestion.
- Materialized view: `CREATE OR REFRESH MATERIALIZED VIEW …`. Always matches its query, so it handles upstream updates and deletes; gold aggregations.
- Trap: changing a streaming table's query affects only new data. A full refresh reprocesses everything but truncates the table first.

**37. Notebook or declarative pipeline?**
- Pipeline: ordering, checkpoints, retries, expectations and CDC are handled for you. If the question says "least code" or "least maintenance", pick the pipeline.
- Notebook plus job: full control, custom logic, API calls, non-table work.
- Order of operations: bronze (raw) → silver (cleaned, deduplicated) → gold (aggregated).
- Triggered mode runs and stops (cheaper); continuous mode stays on (low latency).
- Development mode doesn't retry; production mode retries and restarts.

**38. What do watermarks and output modes do?**
- `withWatermark("event_time", "10 minutes")`: how late data may arrive. It lets Spark drop old state.
- Append: only final rows; an aggregation needs a watermark.
- Update: only changed rows. Complete: the whole result every time.
- Stream-to-stream join: watermark on both sides plus a time-range condition.
- Stream-to-static join: no state; the Delta side is re-read every micro-batch.

**39. Which trigger, and what does the checkpoint do?**
- No trigger set: the next micro-batch starts when the last one ends.
- `processingTime="5 minutes"`: fixed interval.
- `availableNow=True`: process everything available, then stop. Lowest cost for scheduled runs.
- Checkpoint: stores offsets and state. One per query, never shared.
- Upsert from a stream: `foreachBatch` with `MERGE`.

**40. `%run` or `dbutils.notebook.run`, and how do you handle errors?**
- `%run ./nb`: runs inline and shares variables. No return value.
- `dbutils.notebook.run("nb", 600, {"p": "v"})`: separate run with a timeout. Returns the string passed to `dbutils.notebook.exit()`.
- Wrap the call in `try/except` to retry or branch. Raise an exception to fail the task.
- In a job, use task dependencies and "Run if" instead of chaining notebooks.

## J. Jobs and CI/CD

**41. Which job trigger?**
- Scheduled: cron expression with a time zone.
- File arrival: new files in a Unity Catalog external location or volume.
- Table update: a source table changed.
- Continuous: one run is always active and restarts itself. For streaming; no cron.

**42. How do task dependencies, conditions and values work?**
- `depends_on` builds the DAG.
- "Run if" options: `ALL_SUCCESS` (default), `AT_LEAST_ONE_SUCCESS`, `NONE_FAILED`, `ALL_DONE` (cleanup that always runs), `AT_LEAST_ONE_FAILED` (error handler), `ALL_FAILED`.
- Branch with an If/else condition task; loop with a For each task.
- Pass a value: `dbutils.jobs.taskValues.set("k", v)`, read as `{{tasks.taskA.values.k}}`.
- Job parameters reach every task: `{{job.parameters.env}}` or `dbutils.widgets.get("env")`.

**43. A task failed. What are the options?**
- Repair run: re-runs only the failed and skipped tasks plus their downstream tasks. Parameters can be changed.
- Run now: a fresh run of every task.
- Automatic recovery: task retries and timeouts; continuous jobs restart themselves; production pipelines retry.
- Alerts: notifications on start, success, failure or long duration, sent to email, Teams, Slack or a webhook.

**44. What must you know about Asset Bundles?**
```yaml
bundle:
  name: sales
variables:
  catalog:
    default: dev
targets:
  dev:
    mode: development
    default: true
  prod:
    mode: production
    run_as:
      service_principal_name: <app-id>
    variables:
      catalog: prod
```
- CLI order: `databricks bundle validate`, `deploy -t prod`, `run -t prod <job>`, `destroy`.
- `mode: development` prefixes resource names with `[dev <user>]` and pauses schedules.
- Reference values with `${var.catalog}` and `${bundle.target}`.
- CI/CD: GitHub Actions or Azure DevOps runs validate and deploy as a service principal.
- REST option: the CLI is a wrapper over the Workspace, Jobs and Pipelines REST APIs.

**45. What is the Git and testing flow?**
- Git folder: a clone of the repo inside the workspace.
- Flow: feature branch → commit → push → pull request (review and CI in GitHub or Azure DevOps) → merge to main → CI/CD deploys.
- Unit test: one function on a small DataFrame with pytest.
- Integration test: several components together in a test workspace. End-to-end: the whole pipeline.
- UAT: business users accept the result before production.

## K. Monitor, troubleshoot, optimize

**46. Spark UI symptom and fix?**
- Skew (a few tasks far slower or larger than the median): AQE skew join, salt the key, or broadcast the small table.
- Spill (spill memory/disk shown on the stage): more shuffle partitions, fix the skew, or workers with more memory.
- Heavy shuffle (joins, groupBy, repartition): broadcast the small table; filter and select early.
- Driver out of memory: `collect()` or `toPandas()` on large data.
- Where to look: Spark UI for clusters; query profile for SQL warehouses.

**47. What do AQE and caching do?**
- AQE is on by default and does three things at run time: merges small shuffle partitions, switches to broadcast joins, splits skewed partitions.
- Disk cache: automatic local copy of remote Parquet files. Safe.
- `df.cache()`: keeps a computed DataFrame in memory. Use it only when the DataFrame is reused several times, and `unpersist()` afterwards.

**48. OPTIMIZE, VACUUM and time travel?**
- `OPTIMIZE t`: compacts small files and applies liquid clustering. Reads get faster.
- `VACUUM t`: deletes unreferenced files older than the retention (default 7 days). Storage cost drops; time travel shortens.
- Unity Catalog managed tables: predictive optimization runs both automatically.
- History: `DESCRIBE HISTORY t`, `SELECT … VERSION AS OF 5`, `TIMESTAMP AS OF '…'`.
- Rollback: `RESTORE TABLE t TO VERSION AS OF 5`.

**49. How do you track and cut cost?**
- `system.billing.usage` (DBUs per job, cluster and tag) joined to `system.billing.list_prices`.
- Tag compute for chargeback; set budgets.
- Cut cost with job compute instead of all-purpose, autoscaling, auto-termination, spot workers and pools.

**50. How do you send logs to Azure Monitor and alert on them?**
- Azure portal → the Databricks workspace → Diagnostic settings → send log categories (jobs, clusters, notebook, unityCatalog) to a Log Analytics workspace. Needs the Premium tier.
- Query with KQL, in tables such as `DatabricksJobs` and `DatabricksClusters`.
- Alert: an Azure Monitor log alert rule with an action group (email, Teams, webhook).
- Inside Databricks, the alternatives are job notifications and SQL alerts on system tables.
